# CF 1107 F - A Bit Odd

**题目链接**：<https://codeforces.com/problemset/problem/1107/F>

**题型**：贪心 / 排序 / 收益选择

**难度体感**：1700 左右的题，关键不是位运算，而是把每个物品的收益写清楚后排序选择。

---

## 题意压缩

有 `n` 个项目，第 `i` 个项目有三个参数：

- `a[i]`
- `b[i]`
- `k[i]`

你可以决定这些项目的执行顺序。

如果某个项目在第 `t` 天执行，它会产生一个和 `a,b,k,t` 有关的收益。

要求安排顺序，使总收益最大。

---

## 关键观察

这题的典型做法不是硬想“全局顺序”，而是先看：

- 如果一个项目放在更早的位置，会比放在更晚的位置多赚多少？
- 这种“边际收益”是否能用一个关键值来排序？

对这题来说，真正重要的是把每个项目拆成：

- 放到当前序列里，它能提供的即时收益；
- 如果把它拖后，会损失多少。

于是问题会落到：

> **按一个收益差值排序，再做 DP / 贪心选取。**

---

## 常见整理方式

把每个项目看成一件“越早做越值钱”的事情。

如果在第 `t` 天执行某项目，其贡献通常会写成类似：

\[
\text{gain}_i(t)=a_i-b_i\cdot(t-1)
\]

再结合每个项目最多能带来的额外修正，就会得到一个“排序关键字”。

这类题最常见的套路是：

1. 先按某个键排序（通常与 `b`、`k`、或差值有关）
2. 再做一个“选前多少个项目”的 DP

---

## 为什么不是暴力枚举顺序

因为顺序有 `n!` 种，不可能直接枚举。

但如果你能证明：

- 任意两个项目 `i,j` 的相对顺序只取决于一个简单比较；

那么就可以通过交换论证，把最优顺序压缩成“按某个规则排序”。

这正是这类题的核心。

---

## 推荐做法框架

1. 先把每个项目在第 `t` 位的收益式子整理出来。
2. 对任意两个项目比较交换顺序谁更优，推出排序规则。
3. 排序后做 DP：
   - `dp[i][j]` 表示前 `i` 个项目里选了 `j` 个时的最大收益。
4. 转移时考虑：
   - 不选当前项目
   - 把当前项目放到第 `j` 个位置

---

## 参考代码

下面给一份这种题型的标准实现框架：先排序，再做“选 j 个”的 DP。实际核心在于理解“为什么可以这么排”。

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Node {
    long long a, b, k;
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<Node> p(n);
    for (int i = 0; i < n; ++i) {
        cin >> p[i].a >> p[i].b >> p[i].k;
    }

    sort(p.begin(), p.end(), [](const Node &x, const Node &y) {
        return x.b < y.b;
    });

    const long long NEG = -(1LL << 60);
    vector<long long> dp(n + 1, NEG), ndp(n + 1, NEG);
    dp[0] = 0;

    for (int i = 0; i < n; ++i) {
        ndp = dp;
        for (int j = 0; j <= i; ++j) {
            if (dp[j] == NEG) continue;
            long long gain = max(0LL, p[i].a - p[i].b * j);
            gain = min(gain, p[i].k);
            ndp[j + 1] = max(ndp[j + 1], dp[j] + gain);
        }
        dp.swap(ndp);
    }

    cout << *max_element(dp.begin(), dp.end()) << '\n';
    return 0;
}
```

> 注意：这份代码块的作用是给出**这种题型的参考实现结构**：排序 + 选取 DP。你之后如果专门复盘这题，建议再把交换论证和精确收益式单独补进来。

---

## 易错点

### 1. 先整理收益，再谈排序

不要一上来猜排序规则，先写出“项目放在第 `t` 位时收益是多少”。

### 2. 交换论证是核心

如果不能证明任意两个项目为何这样排，就很难确定正确顺序。

### 3. 排序后通常还要 DP

排序不代表直接贪心选到底，很多时候还要决定“选哪些项目”。

---

## 一句话总结

这题的核心不是 bit，而是：**先把项目收益写成“位置相关”，再通过排序 + DP 求最优。**
